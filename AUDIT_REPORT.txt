  NFT-mint.sol (UsernameNFT) — 10 ISSUES FIXED
================================================================================

------------------------------------------------------------------------------
#1  CRITICAL — Empty Token Address (Compilation Error)
------------------------------------------------------------------------------
WHAT:   address public constant cwnTokenAddress = ;
        This is a syntax error. The contract cannot compile.

WHY:    The CAW token address was left empty with no value assigned.

FIX:    Token address is now passed as a constructor parameter:
        constructor(address _cwnTokenAddress) ERC721("CAW", "tCAW") {
            if (_cwnTokenAddress == address(0)) revert InvalidTokenAddress();
            cwnToken = IERC20(_cwnTokenAddress);
        }

        This enables deployment on any network and unit testing with mock tokens.
        Variable declared as "immutable" to save ~2,100 gas per read.

------------------------------------------------------------------------------
#2  CRITICAL — Incorrect approve() in createNFT (Logic Bug)
------------------------------------------------------------------------------
WHAT:   cwnToken.approve(msg.sender, mintCost);
        Called before cwnToken.transferFrom(msg.sender, address(this), mintCost);

WHY:    This line made the NFT contract approve the USER to spend the CONTRACT's
        own tokens. But what transferFrom() needs is the opposite: the USER must
        approve the CONTRACT to spend the USER's tokens.

        In ERC20, approve() sets: allowance[msg.sender][spender].
        When the NFT contract calls approve(), msg.sender = NFT contract address.
        So it sets: allowance[NFT_CONTRACT][user] = mintCost.
        But transferFrom(user, contract, amount) checks: allowance[user][NFT_CONTRACT].
        These are two completely different storage slots. The approve() did nothing useful.

FIX:    Removed the incorrect approve() call. Added a comment explaining that
        the user must call cwnToken.approve(nftContractAddress, mintCost) from
        the frontend before calling createNFT().

------------------------------------------------------------------------------
#3  CRITICAL — No Reentrancy Protection (Security Vulnerability)
------------------------------------------------------------------------------
WHAT:   createNFT() and buyNFT() make external calls without reentrancy guards:
        - cwnToken.transferFrom() calls the CAW token contract
        - _safeMint() calls onERC721Received() on the recipient
        - _safeTransfer() calls onERC721Received() on the recipient

WHY:    If any callback re-enters createNFT or buyNFT before the first call
        completes, an attacker could:
        - Mint multiple NFTs while paying only once
        - Buy an NFT multiple times at the same price
        This is the same class of vulnerability that caused the DAO hack ($60M loss).

FIX:    Added OpenZeppelin ReentrancyGuard with nonReentrant modifier:
        import {ReentrancyGuard} from "@openzeppelin/contracts/security/ReentrancyGuard.sol";
        contract UsernameNFT is ERC721, Ownable, ReentrancyGuard {
            function createNFT(...) external nonReentrant {
            function buyNFT(...) external nonReentrant {

------------------------------------------------------------------------------
#4  CRITICAL — CEI Pattern Violation in buyNFT (Security Vulnerability)
------------------------------------------------------------------------------
WHAT:   Original order in buyNFT():
          1. cwnToken.transferFrom(...)    // external call
          2. _transfer(...)                // external call
          3. salePrice = 0                 // state update (TOO LATE!)

WHY:    The Checks-Effects-Interactions (CEI) pattern requires state updates
        BEFORE external calls. If salePrice is reset after transfers, a reentrant
        attacker could see salePrice > 0 during re-entry and buy again.

FIX:    New order follows CEI:
          1. salePrice = 0                 // state update FIRST
          2. cwnToken.transferFrom(...)    // then external calls
          3. _safeTransfer(...)            // then NFT transfer

        Also replaced _transfer with _safeTransfer for safe recipient checks.

------------------------------------------------------------------------------
#5  CRITICAL — _exists() Removed in OpenZeppelin 4.9.6 (Compilation Error)
------------------------------------------------------------------------------
WHAT:   6 calls to _exists(tokenId) across sellNFT, buyNFT, tokenURI,
        getUsername, and getProfileImageURI.

WHY:    OpenZeppelin removed _exists() starting from version 4.9.0.
        The project uses OZ 4.9.6, so all 6 calls would fail to compile.

FIX:    Replaced all occurrences:
        BEFORE: if (!_exists(tokenId)) revert TokenDoesNotExist();
        AFTER:  if (_ownerOf(tokenId) == address(0)) revert TokenDoesNotExist();

        _ownerOf() returns address(0) for non-existent tokens instead of reverting.

------------------------------------------------------------------------------
#6  MEDIUM — Self-Buy Vulnerability
------------------------------------------------------------------------------
WHAT:   No check preventing a user from buying their own NFT.

WHY:    Self-buying would transfer CAW tokens from the user to themselves
        (pointless, wastes gas), reset salePrice to 0 (accidental delisting),
        and emit a misleading NFTSold event.

FIX:    Added check in buyNFT():
        address seller = ownerOf(tokenId);
        if (seller == msg.sender) revert CannotBuyOwnNFT();

------------------------------------------------------------------------------
#7  MEDIUM — Duplicate require in createNFT
------------------------------------------------------------------------------
WHAT:   The username availability check appeared twice:
        require(usernameToOwner[username] == address(0), "Username already used");
        require(mintCost > 0, "Mint cost must be greater than zero");
        require(usernameToOwner[username] == address(0), "Username already used"); // DUPLICATE

WHY:    Wastes ~200 gas per call for a redundant storage read.

FIX:    Removed the duplicate check.

------------------------------------------------------------------------------
#8  MEDIUM — Missing Purchase Event
------------------------------------------------------------------------------
WHAT:   buyNFT() had no event emission after a successful purchase.

WHY:    Events are essential for:
        - Frontend to detect purchases and update UI in real-time
        - Block explorers to display transaction history
        - Indexers (The Graph, Alchemy) to build query APIs
        - On-chain audit trail

FIX:    Added event definition and emission:
        event NFTSold(uint256 indexed tokenId, address indexed from,
                      address indexed to, uint256 price);
        emit NFTSold(tokenId, seller, msg.sender, salePrice);

------------------------------------------------------------------------------
#9  GAS — String Error Messages Replaced with Custom Errors
------------------------------------------------------------------------------
WHAT:   All require("string message") statements replaced with Custom Errors.

        BEFORE: require(mintCost > 0, "Mint cost must be greater than zero");
        AFTER:  error InvalidMintCost();
                if (mintCost == 0) revert InvalidMintCost();

WHY:    Each string message is stored in contract bytecode. "Mint cost must be
        greater than zero" = 38 bytes. Custom Errors use only a 4-byte selector.
        Gas savings on revert: ~85%. Recommended since Solidity 0.8.4.

        Custom errors defined:
        - UsernameAlreadyUsed()
        - UsernameDoesNotExist()
        - InvalidMintCost()
        - InvalidSalePrice()
        - TokenDoesNotExist()
        - NotTokenOwner()
        - NFTNotForSale()
        - CannotBuyOwnNFT()
        - InvalidTokenAddress()

------------------------------------------------------------------------------
#10 STYLE/GAS — Named Imports, Calldata, NatSpec, Pragma Update
------------------------------------------------------------------------------
WHAT:   Multiple code quality improvements.

(a) Pragma updated from ^0.8.7 to ^0.8.20
    WHY: Enables PUSH0 opcode (saves gas), better compiler optimizations.

(b) Global imports replaced with named imports:
    BEFORE: import "@openzeppelin/contracts/token/ERC721/ERC721.sol";
    AFTER:  import {ERC721} from "@openzeppelin/contracts/token/ERC721/ERC721.sol";
    WHY: Prevents namespace pollution, makes dependencies explicit.

(c) string memory changed to string calldata for external functions:
    BEFORE: function checkUsernameAvailability(string memory username)
    AFTER:  function checkUsernameAvailability(string calldata username)
    WHY: Avoids copying string data to memory, saves gas.

(d) Full NatSpec documentation added to all public/external functions:
    /// @notice Mints a new username NFT
    /// @param username The unique username to register
    WHY: Generates documentation, appears in Etherscan UI, required by solhint.

  GenerateNFT.sol (UsernameSVG) — 3 ISSUES FIXED
================================================================================

------------------------------------------------------------------------------
#11 HIGH — SVG/JSON Injection (On-Chain XSS)
------------------------------------------------------------------------------
WHAT:   Username inserted directly into SVG and JSON without sanitization:
        '<text ...>', username, '</text>'
        '{"name": "', username, '", "description": "...'

WHY:    A username like:  </text><script>alert('hacked')</script><text>
        would inject executable JavaScript into the SVG. NFT marketplaces
        (OpenSea, Blur, LooksRare) render SVG images in the browser.
        This is a stored XSS vulnerability that lives permanently on-chain.

        For JSON, a username like:  ", "evil": "value
        would break the JSON structure and allow field injection.

FIX:    Added _sanitize() function that escapes 5 dangerous characters:
        < becomes &lt;    (prevents SVG tag injection)
        > becomes &gt;    (closes injected tags)
        " becomes &quot;  (breaks out of JSON strings)
        ' becomes &#39;   (breaks out of attribute values)
        & becomes &amp;   (prevents entity injection)

        The sanitized string is used in both SVG and JSON output.

------------------------------------------------------------------------------
#12 LOW — No Username Length Validation
------------------------------------------------------------------------------
WHAT:   No limit on username length passed to generate().

WHY:    A 10,000+ character username would generate an enormous SVG and require
        excessive gas for Base64 encoding. As a view function this is free, but
        if generate() is called from another contract in a transaction, it
        becomes a Denial of Service vector.

FIX:    Added constant and validation:
        uint256 public constant MAX_USERNAME_LENGTH = 32;
        if (len == 0) revert EmptyUsername();
        if (len > MAX_USERNAME_LENGTH) revert UsernameTooLong();

------------------------------------------------------------------------------
#13 INFO — Unused Import
------------------------------------------------------------------------------
WHAT:   import "@openzeppelin/contracts/utils/Strings.sol";

WHY:    Strings library was imported but never used in the contract.
        Increases bytecode size and deployment cost unnecessarily.

FIX:    Removed the import.
